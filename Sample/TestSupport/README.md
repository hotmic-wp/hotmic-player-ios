# Public SDK regression support

Select **HotMicPlayerRegression** in `Sample/HotMicPlayerDemo.xcodeproj`. Partner code under `HotMicPlayerDemo` uses public imports. This separate synchronized source group compiles only in DEBUG; it supplies native identity probes, generated media and explicit host commands for SDK behavior acceptance. It has no benchmark grid, repeats, upload/export runner or Device Farm integration.

`PlayerRegressionUITests.testNativeCancelledDragAndLift` runs offline by default using the existing synthetic court generator. It preserves both slow cancelled-drag directions, no transient activation, lift commit, pause-burst/back navigation and the two-player bound. The horizontal restricted-host and fullscreen continuity tests preserve native assignment/activation, first-frame/stall counts, host-sheet return, rotation restrictions, inline/feed continuity and immediate paging after exit. Ads, overlay, moderation, scrub cancellation, partner integration and video-gesture tests remain public.

For the HTTP MP4/HLS path and both horizontal tests, generate a small generic fixture set with Python 3 and ffmpeg, from the repository root:

```bash
python3 Sample/TestSupport/serve-fixtures.py
```

The server binds loopback only, supports byte ranges and writes synthetic media under ignored `.bench/public-fixtures`. It does not download or bundle media. Keep it running while testing on an owned dedicated simulator. Use the same manifest for native acceptance and horizontal continuity:

```bash
TEST_RUNNER_HM_NATIVE_ACCEPTANCE_MANIFEST=http://127.0.0.1:18490/manifest.json \
TEST_RUNNER_HM_HORIZONTAL_MANIFEST=http://127.0.0.1:18490/manifest.json \
xcodebuild test -project Sample/HotMicPlayerDemo.xcodeproj -scheme HotMicPlayerRegression \
  -destination 'platform=iOS Simulator,id=SIMULATOR_UDID' \
  -only-testing:HotMicPlayerDemoUITests/PlayerRegressionUITests \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO
```

Replace `SIMULATOR_UDID` with your dedicated simulator. Stop the fixture server with Ctrl-C afterwards. Native cancellation can run without either variable; horizontal tests skip unless their manifest is supplied. Optional custom manifests use the same nonempty unique-ID array as the demo, with `format`, `duration`, `aspectRatio` and relative `captions` language URLs. The horizontal walkthrough expects `001-portrait`, `002-landscape`, `003-portrait` and `004-landscape` in MP4/MP4/HLS/HLS order, as generated by the helper. No private checkout or fixtures are required.

DEBUG launch routes `--hm-ads-lab 1`, `--hm-horizontal-lab 1`, `--hm-reference-lab 1` and `--hm-accessibility-lab 1` are harness hosts, separate from normal demo navigation. The captions host uses the helper's `fixture/clip.mp4`, `fixture/master.m3u8` and sidecar VTT files at `--hm-lab-origin http://127.0.0.1:18490`; embedded subtitle-selection scenarios can supply their own public fixture variant. Ads and social/partner gesture hosts generate their media in the app. `--hm-probe 1` enables feed acceptance status and the DEBUG host notification commands; normal partner launches do not enable them.

The old grid wrapper in `BenchmarkUITests.testBenchmarkGrid` moved with the external benchmark runner. Its native acceptance branch is retained under the new descriptive name; the two horizontal test functions retain their assertions, with added runtime details in failure messages. Scripted ranked-refresh, synthetic mid-swipe orchestration, offline-page logging and benchmark diagnostics were removed from the partner playlist screen; their SDK contracts remain in public native/unit tests and the external lab. No SDK behavior test was removed because its old file was named Benchmark. Suite size is unchanged; only the grid-only branch and duplicate runner logic were removed. Simulator evidence establishes behavior, not physical-device performance.
